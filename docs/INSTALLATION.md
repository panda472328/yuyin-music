# Windows 安装与重装

安装保护从 PC 0.4.12 起随正常版本提供，不另发修复包；0.4.11 构建失败，没有公开安装文件。以对应版本的 GitHub Release 和 SHA-256 为准，不用重新构建的不同文件替换历史附件。

## “余音无法关闭”或无法写入 Uninstall 余音.exe

0.4.9／0.4.10 的安装器可能在旧程序或卸载程序仍被占用、目录没有写入权限，或旧版卸载失败时出现这两种提示。仅凭错误截图不能确认是哪一种；重试并不授予目录权限，也不能释放仍被占用的文件。

1. 在旧安装器的写入失败窗口选择“中止”，关闭此前的安装和卸载窗口；不要选择“忽略”继续安装。
2. 正常退出余音，包括桌面歌词窗口。如果窗口已关闭但后台程序仍在，或旧卸载窗口关不掉，可先重启 Windows。
3. 将安装包放在下载或桌面目录，从那里启动；不要把安装包放在准备覆盖的余音安装目录里面。
4. 普通安装选择“仅为我安装”及默认目录。`Program Files` 或其他管理员管理的目录需要选择“为所有用户安装”并由用户允许管理员权限。管理员权限不能代替退出仍在使用文件的程序。
5. 使用当前正式版完整安装包重新安装，再从快捷方式启动。如果仍失败，提供版本、安装目录和完整错误文本。不要提供账号 Cookie、个人音乐库或 profile。

如果此前点过“忽略”，程序文件可能没有安装完整，应重新运行完整安装包。收藏和设置保存于 `%APPDATA%/YuyinMusic`，与安装目录分开；不要通过删除该目录来处理安装文件占用。

## 0.4.12 的安装检查

安装器扩展位于 `build/installer.nsh`，通过 `package.json` 的 `build.nsis.include` 接入。保持现有 appId、注册身份、EXE 名称及数据目录。

- 安装前检查最终目标和相关旧安装目录是否可写，临时探针仅使用唯一新文件。
- 使用 Windows `CreateFileW` 检查确切应用和卸载文件是否可写，不截断文件、不遍历或强杀目录内进程；其他目录中的同名程序不作为新检查的目标。
- 安装包位于待覆盖目录内部时停止，要求先移到下载或桌面目录。
- 文件占用时可在正常退出后重试；取消和静默失败均返回非零退出码 `2`。
- 旧卸载无法启动、非零退出，或返回成功却仍保留旧程序时，停止安装，不进入新的文件覆盖。
- 可见安装在上游目录整理后预检；静默安装在安装模式与 `/D` 解析后预检，管理员安装在已提权的实例检查。

从 0.4.9／0.4.10 升级仍会运行其原有卸载程序。新 include 无法改写已安装的旧卸载器；旧目录有其他正在运行的程序或旧卸载器本身失败时，应先退出相关程序，再重试。错误会被新安装器拦截，但不声称旧卸载器自身的全部行为已修复。

## 验证入口

```sh
npm run dist:installer -- --x64 --publish never
npm run test:installer
```

原生测试用 NSIS 编译仓库宏与无害进程，在 `.qa/installer-guards-*` 验证占用、只读、路径边界、静默／页面回调和卸载结果；不执行真实安装，不写安装注册项、快捷方式或真实用户数据。Windows 发布工作流在打包后强制执行此测试。非 Windows 或缺少编译器的本地运行会明确标为跳过；CI 用 `YUYIN_REQUIRE_INSTALLER_TESTS=1` 使缺失依赖成为失败。

完整首次安装、旧版覆盖升级和跨用户管理员权限需要在独立 Windows 虚拟机或 Windows Sandbox 继续验收。宏回归及“锁定时提前退出”的成品检查不能替代这些生命周期测试，详见 [QA.md](QA.md)。
